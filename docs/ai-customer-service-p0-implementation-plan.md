## 1. 已采用的默认决策

在没有新的业务约束前，P0 按以下方案执行：

| 决策项 | P0 选择 | 原因 |
| --- | --- | --- |
| 用户渠道 | 只接入 `sky-web-user` | 先减少渠道和会话同步复杂度 |
| Agent 形态 | 受控单 Agent + 确定性工作流 | 容易测试、审计和限制权限 |
| AI 服务 | 仓库内新增独立 `sky-ai-service`，独立进程 | 不迫使 Spring Boot 2.7.3/Java 9 交易内核立即升级 |
| AI 运行时 | Java 21 LTS | 已由独立 `sky-ai-service/pom.xml` 锁定 |
| AI 框架 | Spring Boot 4.1.0 + Spring AI 2.0.0 | 独立构建，不升级交易内核 |
| 模型 | 阿里云百炼 Qwen 第一候选 | 国内访问和 OpenAI-compatible 接入方便 |
| 模型耦合 | Provider Adapter | 允许后续切换模型和地域 |
| 流式协议 | SSE | 适合首期请求-响应式流式文本 |
| P0 工具 | `get_shop_status`、`get_order_progress` | 最小化验证实时查询与用户权限链路 |
| 人工接管 | 创建简易客服工单 | 先形成可处理的升级闭环，不立即建设实时坐席系统 |
| RAG | P0 PoC 后半段再加入 | 先验证身份、工具、安全和流式链路 |
| 业务写操作 | 全部关闭 | P0 不取消、退款、支付、催单或修改购物车 |

版本号在开始编码时根据 Spring AI 官方兼容矩阵锁定，并写入 Maven 属性；禁止使用 `LATEST`、版本范围或未固定的快照版本。

## 2. P0 范围与完成定义

### 2.1 P0 必须具备

- 登录用户可以从 Web 客服页发起新会话；
- AI 能实时回答当前店铺是否营业；
- AI 能查询当前用户本人的订单状态和预计送达时间；
- 多笔订单时先让用户选择，不擅自选择；
- AI 不知道、工具失败、用户要求人工或命中风险规则时创建客服工单；
- 用户能看到流式回复、错误提示和人工移交状态；
- 服务端保存完整用户可见消息、工具审计和工单；
- 模型、工具或 AI 服务故障不能影响浏览、购物车、下单和订单查询主链路；
- 固定安全用例全部通过后才能对白名单用户开放。

### 2.2 P0 明确不做

- 不自动取消订单、催单、退款、支付或加入购物车；
- 不提供骑手实时位置；
- 不回答未经确认的营业时间、退款时效、配送费或过敏原；
- 不接入小程序、多渠道或语音；
- 不做多 Agent；
- 不直接复用当前广播式 `/ws/{sid}`；
- 不让 AI 服务直接访问交易库的业务表。

### 2.3 P0 Definition of Done

同时满足以下条件才算完成：

1. 功能验收通过；
2. 跨用户订单访问、Prompt Injection 和未授权写操作测试 100% 通过；
3. 工具失败不会产生虚构答案；
4. 人工接管后 Bot 不再回复；
5. AI 故障不影响交易服务；
6. 能按会话追踪模型调用、工具调用、耗时和错误；
7. 支持配置开关一键关闭 AI 回复；
8. 具备清晰的部署、回滚和密钥配置说明；
9. 已完成白名单灰度和人工抽检；
10. 知识与风险话术已由责任人审核。

## 3. 建议的仓库结构

以下是目标结构；其中 `sky-ai-service` 的 P0 骨架、API、模型适配、鉴权、工具客户端、三张核心表持久化和最小 SSE 已经创建：

```text
sky-take-out/
├─ sky-ai-service/
│  ├─ pom.xml
│  └─ src/
│     ├─ main/java/com/sky/ai/
│     │  ├─ api/                 # 会话与 SSE 接口
│     │  ├─ application/         # 用例编排、会话状态机
│     │  ├─ agent/               # Prompt、模型调用、工具循环
│     │  ├─ provider/            # 模型 Provider Adapter
│     │  ├─ tool/                # 模型可见工具定义
│     │  ├─ client/              # 调用 sky-server 内部工具门面
│     │  ├─ guardrail/           # 输入、输出、权限与风险规则
│     │  ├─ handoff/             # 简易人工工单
│     │  ├─ persistence/         # 会话、消息、审计存储
│     │  ├─ observability/       # 指标和 Trace
│     │  └─ config/
│     └─ test/
├─ sky-server/
│  └─ src/main/java/com/sky/
│     ├─ controller/internal/    # AI 专用内部门面
│     ├─ service/                # 用户范围内的安全查询
│     └─ dto/vo/                 # 最小字段 DTO
├─ sky-web-user/
│  └─ src/
│     ├─ views/                  # 客服会话页
│     ├─ components/             # 消息、来源、订单卡片
│     ├─ api/                    # 会话/SSE API
│     └─ stores/                 # 会话状态
├─ sql/
│  └─ ai-customer-service.sql    # AI 独立表，不改原业务表
└─ evals/
   └─ customer-service-p0/       # 可执行评测数据与结果
```

如果根 Maven 父工程无法安全管理两代 Spring Boot，`sky-ai-service` 不应继承当前根 `pom.xml`，而应使用独立 Maven 工程；是否加入根 `<modules>` 必须在验证 Maven 构建隔离后决定。

## 5. M0：需求、版本与安全冻结

### `AI-0001` 审核 P0 知识

- 责任角色：产品、运营、客服；
- 输入：`ai-customer-service-p0-spec.md` 第 3 节；
- 工作：为每条知识指定责任人、版本、生效时间和正式话术；
- 输出：已批准和仍禁止自动回答的知识清单；
- 验收：所有生产知识都有责任人，没有“默认按常识回答”的条目。

### `AI-0002` 确认人工工单接收方

- 责任角色：产品、客服；
- 工作：确定由谁查看工单、服务时段、优先级和关闭规则；
- 默认方案：先在管理端新增只读列表和详情，人工在系统外联系用户；
- 验收：食品安全、支付争议和普通咨询分别有明确接收人。

### `AI-0003` 锁定运行时和框架版本

- 责任角色：后端、运维；
- 工作：验证选定 JDK、Spring Boot、Spring AI 和 Maven 版本兼容；
- 需要验证：普通响应、SSE、工具调用、超时和 Token Usage；
- 输出：版本矩阵和最小 Hello Model 实验记录；
- 验收：依赖可从团队 Maven 源稳定下载，无快照和传递依赖冲突。

### `AI-0004` 确认模型和数据策略

- 责任角色：产品、后端、合规；
- 工作：确认百炼地域、模型候选、数据保留、内容审核和月预算；
- 输出：Provider 配置项和禁止发送字段清单；
- 验收：API Key 不进入仓库，手机号、地址、密码和支付凭证有明确最小化策略。

### `AI-0005` 完成威胁建模

- 责任角色：后端、测试；
- 至少覆盖：跨用户订单、伪造用户上下文、Prompt Injection、工具参数注入、敏感日志、重复工单、SSE 重放和模型无限循环；
- 输出：威胁—控制—测试用例映射；
- 验收：每个高风险威胁至少有一个代码控制和一个自动化测试。

## 6. M1：安全的业务工具门面

### `AI-0101` 设计服务身份和用户上下文

- 责任角色：后端；
- 推荐：服务 JWT + 60 秒内有效的签名用户上下文；
- 用户上下文包含：`sub`、`aud`、`conversationId`、`iat`、`exp`、随机 `jti`；
- 禁止：明文 `X-User-Id`、模型参数中的 `userId`、长期可重放令牌；
- 验收：过期、错误 audience、篡改和重放均被拒绝。

### `AI-0102` 实现店铺状态内部接口

- 对应工具：`get_shop_status`；
- 业务输出：`OPEN`、`CLOSED`、`UNKNOWN` 和 `checkedAt`；
- 关键规则：Redis 缺失或类型异常映射为 `UNKNOWN`，不能映射为打烊；
- 测试：营业、打烊、Redis 无值、Redis 超时和畸形值。

### `AI-0103` 实现用户范围内订单查询

- 对应工具：`get_order_progress`；
- 查询条件必须同时包含 `orderId` 和认证后的 `userId`；
- 输出只包含：状态、状态文案、预计/实际送达时间、允许操作、详情路径；
- 不返回：完整电话、地址、备注和支付凭证；
- 验收：U1 查询 U2 订单时不返回任何 U2 字段。

### `AI-0104` 由业务代码计算允许操作

- 输出枚举：`VIEW_DETAIL`、`REQUEST_CANCEL`、`REQUEST_HANDOFF`；
- 规则来源：现有订单状态和用户取消约束；
- 关键原则：模型只读取 `allowedUserActions`，不能自行决定订单能否取消；
- P0 中 `REQUEST_CANCEL` 只用于页面引导，不提供取消工具。

### `AI-0105` 统一工具错误模型

- 实现稳定错误码、可重试标记和 Trace ID；
- 内部异常、SQL、堆栈和依赖地址不得进入模型上下文；
- 验收：超时、订单不存在、越权、参数错误和内部异常均符合契约。

### `AI-0106` 修复现有订单读取边界

- 至少修复或隔离 `details(id)` 的订单归属问题；
- 催单和再来一单在 P0 不暴露，但应创建独立安全整改任务；
- 验收：安全门面不调用无法保证归属的旧方法。

## 7. M2：AI 服务最小链路

### `AI-0201` 创建独立 AI 服务骨架

- 建立独立 Maven 构建、健康检查和分环境配置；
- 不加入业务库 Mapper，不获得业务数据库账号；
- 配置启动失败条件：生产环境缺少模型 Key 时明确失败或按预设禁用 AI；
- 验收：单独构建、测试和启动，不影响根项目原构建。

### `AI-0202` 实现 Provider Adapter

- 统一流式聊天、工具调用、错误、Token 和模型信息；
- 模型相关配置全部外置：`provider`、`baseUrl`、`apiKey`、`model`、超时；
- 为百炼兼容接口添加契约测试；
- 验收：替换测试 Provider 时，业务编排代码无需修改。

### `AI-0203` 建立系统指令和输出边界

- 指令必须说明角色、允许事实来源、禁止事项、工具边界和升级规则；
- 用户文本、工具结果和知识片段使用结构化边界隔离；
- 不在 Prompt 中写入密钥、内部 URL 或数据库信息；
- 输出过滤手机号、地址、验证码和可能的系统提示泄露。

### `AI-0204` 实现会话状态机

- 状态：`BOT_ACTIVE`、`WAITING_HUMAN`、`HUMAN_ACTIVE`、`RESOLVED`、`DEGRADED`；
- 状态切换使用乐观锁或条件更新；
- `WAITING_HUMAN/HUMAN_ACTIVE` 时阻止 Bot 新回复；
- 验收：并发用户消息和人工接管不会产生双回复。

### `AI-0205` 实现模型工具注册表

- 首批只注册 `get_shop_status` 和 `get_order_progress`；
- 工具 Schema 使用 `additionalProperties=false`；
- 单轮业务工具最多 3 次，Agent 循环最多 5 步；
- 未知工具或越界参数必须拒绝；
- 验收：模型无法发现或调用取消、退款、支付、SQL 等工具。

当前完成情况：已用请求级 `FunctionToolCallback` 注册 `get_shop_status` 和
`get_order_progress`。订单工具仅在请求携带合法订单 ID 时出现，且两个工具均不接受模型生成的
身份或资源 ID；同一轮同一工具只执行一次。取消、退款、支付和任意访问能力未注册。

### `AI-0206` 实现确定性路由和升级规则

- 明确要求人工、食品安全、过敏原、支付争议和账户安全不交给模型自由判断；
- 连续未解决、工具失败和负面情绪进入升级路径；
- 用户未登录询问订单时直接引导登录，不尝试工具调用；
- 验收：高风险固定用例 100% 命中正确路径。

当前完成情况：已落地三层意图管线首切片。规则层覆盖门店、订单、退款和订单 ID；上下文层
读取同一用户同一会话最近消息，并在订单工具成功后使用 `related_order_id` 保存受控订单槽位；
前两层无法确定时进入 Qwen Function Calling。统一 `PolicyEngine` 和 `CapabilityRegistry`
控制可见工具，退款固定返回 `UNSUPPORTED_WRITE` 且不调用模型或工具。取消、催单、支付争议、
食品安全、人工升级和更完整的结构化 LLM 意图评测仍待后续切片。

### `AI-0207` 实现超时、重试和熔断

- 只对明确可重试且尚未产生副作用的请求重试；
- 模型和工具分别设置超时，轮次设置总超时；
- 限制并发、消息长度、Token 和每用户频率；
- 验收：模型不可用时返回固定降级结果，不拖慢交易服务。

## 8. M3：会话存储与用户端

### `AI-0301` 建立 AI 数据表

- 表：`ai_conversation`、`ai_message`、`ai_tool_call`、`ai_handoff`、`ai_feedback`；
- 所有表包含创建时间，状态表包含版本号；
- 工具表只保存脱敏参数摘要；
- SQL 使用独立迁移文件，不改变原订单表；
- 验收：支持会话历史、工具审计、工单和反馈查询。

### `AI-0302` 实现会话 API

- 新建会话、查询会话、分页历史、发送消息、反馈和申请人工；
- 每个会话接口校验当前用户归属；
- 请求提供幂等键，重复提交不重复保存消息；
- 验收：U1 无法读取 U2 会话。

当前完成情况：已完成新建会话、本人会话列表、本人会话详情和历史消息游标分页；真实 JWT + MySQL 集成测试已验证 U1 无法读取 U2 会话。发送消息、反馈和申请人工仍待后续切片。

### `AI-0303` 实现 SSE 事件协议

- 事件：`message.delta`、`message.completed`、`source`、`card`、`handoff`、`error`；
- 每个事件有 `eventId`、`conversationId` 和时间；
- 支持客户端去重；是否支持断点续传由 PoC 验证后锁定；
- 验收：中途断开不会重复创建消息或工单。

当前完成情况：已实现 `message.delta`、`message.completed`、`error`，事件 ID 基于助手消息 ID 稳定生成；重连复用 `clientRequestId` 并携带 `Last-Event-ID` 时只发送后续事件，不重复创建消息或调用工具。`source`、`card`、`handoff` 和模型原生 Token 流仍待后续切片。

### `AI-0304` 创建用户端客服页

- 展示 AI 身份、隐私提示、快捷问题和人工入口；
- 支持消息流、加载/失败/重试、订单选择卡片和人工状态；
- 不把模型返回内容用未净化的 HTML 直接渲染；
- 验收：移动端布局可用，网络断开有明确反馈。

当前完成情况：已新增 `/support` 用户端客服页，展示 AI 身份与隐私提示，支持快捷问题、会话创建/切换、历史分页加载、POST SSE 消息流、稳定请求 ID、断线续传、失败重试和手工填写订单 ID；模型内容使用文本插值渲染。人工入口、订单选择卡片和人工状态仍待后续切片。

### `AI-0305` 接入用户认证

- 延用用户端 JWT 作为对外身份；
- AI 服务验证令牌后生成短期内部用户上下文；
- 过期令牌统一引导登录；
- 验收：前端参数不能覆盖服务端用户身份。

## 9. M4：简易人工工单

### `AI-0401` 实现 `create_handoff`

- 工单包含：用户、会话、原因、关联订单、摘要、优先级和 Trace；
- 摘要由模型生成后由服务端补充事实，不能作为唯一记录；
- 使用幂等键避免重复工单；
- 成功创建后会话进入 `WAITING_HUMAN`。

### `AI-0402` 实现服务端优先级规则

- `FOOD_SAFETY`、`PRIVACY_SECURITY`、`PAYMENT_DISPUTE` 默认为高优先级；
- 普通人工请求和未解决问题按常规优先级；
- 模型建议不能降低强制高优先级；
- 验收：风险原因和优先级由代码决定。

### `AI-0403` 提供最小管理端查看能力

- 列表：状态、优先级、原因、创建时间、用户脱敏信息；
- 详情：完整会话、工具轨迹、关联订单摘要和 AI 摘要；
- 权限：只对有客服权限的管理员开放；
- P0 可不实现站内实时回复，但必须允许标记已接收、处理中和已关闭。

### `AI-0404` 防止 Bot 与人工双回复

- 人工接收或处理时更新会话控制权；
- 所有生成任务在真正发送前再次检查状态；
- 已经排队但尚未发送的 Bot 回复在人工接管后丢弃；
- 验收：并发接管测试中只存在一个回复方。

## 10. M5：评测、观测与灰度

### `AI-0501` 将评测用例转换为机器数据

- 格式：JSONL 或 YAML；
- 每条包含：输入、上下文、测试身份、模拟工具结果、允许/禁止工具、事实断言、升级断言和敏感内容断言；

### `AI-0502` 构建确定性测试 Harness

- 使用真实候选模型运行工具选择与回答质量评测；
- 评测结果记录模型、Prompt、知识版本和时间；
- 验收：同一版本结果可复现和比较。

### `AI-0503` 建立安全回归

- 覆盖跨用户订单、用户 ID 注入、系统提示窃取、恶意知识文档、未知工具、参数溢出和敏感信息；
- 安全用例任何一条失败都阻止发布；
- 真实模型升级、Prompt 修改和工具新增必须重新运行。

### `AI-0504` 建立可观测性

- 指标：请求量、错误率、首字/完整延迟、Token、工具耗时、工具错误、升级原因、会话结果；
- Trace 串联：前端请求、AI 轮次、模型、工具和业务服务；
- 默认不记录完整 Prompt、工具参数和模型正文；
- 验收：能够从一个 `conversationId` 定位失败阶段。

### `AI-0505` 压测和故障演练

- 场景：模型慢、模型 429/500、业务工具超时、Redis 异常、数据库慢、SSE 断开和请求风暴；
- 验证 AI 限流与交易接口资源隔离；
- 确认熔断、降级和恢复行为；
- 输出容量基线和告警阈值。

### `AI-0506` 白名单灰度

- 阶段：开发人员账号 → 内部用户 → 1% 白名单 → 更高比例；
- 灰度按用户稳定哈希，不随机切换同一会话；
- 每阶段抽检全部高风险会话和至少 10% 普通会话；
- 触发越权、错误政策或重复工单时立即关闭 AI 开关。

## 15. 发布与回滚方案

### 发布前

- 数据库迁移只新增 AI 表，不修改订单主表；
- AI 服务和页面入口由功能开关控制；
- 先部署后端和 AI 服务，健康后再对白名单展示入口；
- 保存当前 Prompt、模型、知识和评测版本。

### 快速停用

- 关闭 `AI_ENABLED` 后拒绝新 Bot 轮次；
- 已有会话显示固定维护提示和人工入口；
- 不删除历史消息和工单；
- `sky-server` 原用户接口继续工作。

### 回滚

- 前端隐藏客服入口；
- 下线 AI 服务；
- 保留新增 AI 表，避免破坏审计；
- 因为 P0 不修改订单状态，回滚不需要恢复业务订单数据。
